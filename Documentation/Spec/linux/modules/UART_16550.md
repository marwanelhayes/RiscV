# `uart_16550.sv` — 16550-compatible console UART (subset)

Spec: register offsets and bits as used by Linux's 8250 driver
([include/uapi/linux/serial_reg.h](https://github.com/torvalds/linux/blob/master/include/uapi/linux/serial_reg.h)),
DT binding [serial/8250.yaml](https://github.com/torvalds/linux/blob/master/Documentation/devicetree/bindings/serial/8250.yaml).
The original part datasheet (National/TI PC16550D) is the historical reference; I
could not fetch it in this audit. Plan block B7.5. Back to [index](../README.md).

## 1. Purpose

The console for OpenSBI (`fdt_serial_uart8250.c` matches `ns16550`/`ns16550a`,
[OpenSBI](https://github.com/riscv-software-src/opensbi/tree/master/lib/utils/serial)),
Linux earlycon (`OF_EARLYCON_DECLARE(ns16550a, …)` in
[8250_early.c](https://github.com/torvalds/linux/blob/master/drivers/tty/serial/8250/8250_early.c))
and the Linux `ttyS0` driver. The DT node with `compatible = "ns16550a"` makes the OF
driver use a fixed port type (`UPF_FIXED_TYPE`,
[8250_of.c](https://github.com/torvalds/linux/blob/master/drivers/tty/serial/8250/8250_of.c)),
so the driver does not probe the FIFO depth by autoconfig — a modest subset works.

## 2. Register map (`reg-shift = 0`, byte registers, base `0x1000_0000`)

| Off | DLAB=0 read | DLAB=0 write | DLAB=1 | Subset behaviour |
|---|---|---|---|---|
| 0 | RBR (`UART_RX`) | THR (`UART_TX`) | DLL | RX: pop the RX FIFO. TX: emit byte on `TxByte/TxValid` immediately |
| 1 | IER | IER | DLM | bits 0 RDI, 1 THRI, 2 RLSI, 3 MSI stored |
| 2 | IIR | FCR | — | IIR bit 0 = 1 "no interrupt"; ID `0x04` RX data, `0x02` THR empty; bits 7:6 = `11` when FIFOs enabled. FCR: accept, store FIFO-enable |
| 3 | LCR | LCR | LCR | stored; bit 7 = DLAB |
| 4 | MCR | MCR | MCR | stored (loopback bit 4 may be ignored) |
| 5 | LSR | — | — | bit 0 DR = RX FIFO non-empty, bit 5 THRE = 1, bit 6 TEMT = 1 (TX is instantaneous) |
| 6 | MSR | — | — | return `0xB0` (CTS, DSR, DCD set) or 0; driver tolerates both for a console |
| 7 | SCR | SCR | SCR | plain R/W byte |

Divisor latches are stored but ignored (no baud generation in simulation). DT
`clock-frequency` is still required by the binding; any consistent value works.

## 3. Ports

AXI4 slave (same port list as `Design/risc_data_memory.sv`; single-beat byte
accesses, honour `MWStrb`), plus:

```
output logic [7:0] TxByte,
output logic       TxValid,      // one cycle per THR write
input  logic [7:0] RxByte,       // from the TB (keyboard script)
input  logic       RxValid,
output logic       Irq           // (IER.RDI & DR) | (IER.THRI & THRE)  -> PLIC source 10
```

## 4. Integration notes

- Region uncached (RBR reads pop a byte — a cached or burst read would lose input).
- THRE-interrupt semantics: on a real 16550, the THR-empty interrupt is cleared by
  reading IIR or writing THR, and re-raised when THR empties. With "TX is
  instantaneous", THRE is always 1, so `IER.THRI = 1` gives a permanent interrupt —
  clear the THRE source on IIR read and re-arm on the next THR write, or the kernel
  will see an interrupt storm once PLIC wiring is enabled. In polled mode (no
  `interrupts` in the DT) this does not matter.
- TB side: `$write("%c", TxByte)` into `uart.log` (PLAN_B B7.5). That log is the
  pass/fail evidence for every boot test.

## 5. Verification hooks

- Small env with RAL (frontdoor) + byte-stream scoreboard: every THR write appears
  once on `TxByte`; every injected `RxByte` is read once from RBR, in order.
- SVA: `DR == (rx_count != 0)`; IIR priority (RX data over THR empty).
- System: OpenSBI banner, then `earlycon=sbi` / `earlycon=uart8250,mmio,0x10000000`
  messages, then the BusyBox prompt.
