## B4 Supervisor mode (B4.1 S CSRs, delegation, SRET; B4.2 interrupt arbitration)
- Goal:            Add S-mode to the M/U core (`misa.S`, S CSRs as views of M state, `medeleg`/`mideleg`, trap entry to S, SRET with TSR, writable `mip.SSIP/STIP/SEIP`, `scounteren`, ECALL cause 9, S external line, per-target interrupt arbitration). - Design files:    new: none   modified: `shared_pkg.sv`, `csr_defs.sv`, `csr_file.sv`, `execute_stage.sv`, `decode_stage.sv`, `riscv_processor.sv` (`hazard_unit.sv` unchanged)

### Commit-point timing (all of B4)
Unchanged from B3 (PLAN_B §2.3): for the EX instruction in cycle *t*, `Commit = ValidE && !StallE` (`execute_stage.sv:465`).
- Trap routing (`ToS`), SRET legality and the interrupt choice are combinational in *t* from `PrivMode`, `Medeleg`, `Mideleg`, `MStatus*`, `Mie/Mip`; the redirect `CsrOutPC` is combinational in *t* (`csr_file.sv:292-298` gains the S arms), the EX instruction is squashed, F/D are flushed by `TrapIsSet`.
- All state changes (`PrivMode`, `Sepc/Scause/Stval`, `SIE/SPIE/SPP`, `Medeleg/Mideleg`, `Mip` software bits) happen at the edge ending *t*; the next EX instruction sees them, no flush needed. The existing `!Commit |=> $stable` rule (`csr_sva.sv:41`) extends to every new register.
- `Mip.SSIP/STIP/SEIP` software bits written by a CSR instruction are visible to the next instruction's interrupt check, as in Spike (`take_interrupt` runs before each fetch, `processor.cc:296`).

**satp decision (TVM + satp): introduce now as read-zero WARL, defer storage and TVM to B5.** Spike with S and no MMU does exactly this: `satp` exists, reads 0 (`csrs.cc:1264`); `mstatus.TVM/SUM/MXR` are not in the write mask (`:715`, `:598`); `SFENCE.VMA` raises illegal even in M (`insns/sfence_vma.h:2`, `require(has_mmu())`). `rv*mi-p-illegal` has a "bare S" path for exactly this core (`illegal.S:75-79,111-131`: SUM/MXR read back 0, SFENCE.VMA traps, TVM stays 0, `csrr satp` does not trap). Making `satp` real now would require `spike_dpi` to call `set_max_vaddr_bits(32/39)`, which turns Spike's MMU on and breaks lock-step (the DUT does not translate). So TVM has nothing to gate yet, and decode keeps SFENCE.VMA illegal (`decode_stage.sv:442-456`, rs1/rs2 ≠ 0 is already `SystemIllegalD`). B5.0 turns `has_mmu` on (`proc->set_max_vaddr_bits`), adds SUM/MXR/TVM, real `satp`, SFENCE.VMA and FIOM.

RTL notes: `CsrExists` gains the rows above (`medelegh` with `!IS_RV64`); `MSTATUS_SXL64 = 64'd2 << 34` (zero at RV32, same trick as UXL, `csr_file.sv:60`); `MISA_VALUE` ORs `1 << MISA_S` (`:40-47`); `medeleg`/`mideleg` cases in the read mux (`csr_file.sv:~160`) return the stored registers instead of 0.

### B4.2 Interrupt arbitration
One `always_comb` in `csr_file` replaces `InterruptPending/InterruptCause` (`:269-280`), outputs `IrqPending`, `IrqCause`, `IrqToS`. Targets are resolved in groups, M first (Spike `processor.cc:322-340`; TRAP_COMMIT_UNIT §3 "M-targeted first"):
```systemverilog
Pend  = MipValue & MieValue;
EnM   = (PrivMode != MachineMode) || MStatusMIE;                           // M ints always on below M
EnS   = (PrivMode == UserMode) || (PrivMode == SupervisorMode && MStatusSIE);   // never in M
IrqM  = Pend & ~MidelegMask & {EnM}; IrqS = Pend & MidelegMask & {EnS};
Sel   = (|IrqM) ? IrqM : IrqS;   IrqToS = !(|IrqM) && (|IrqS);   IrqPending = |Sel;
IrqCause = Sel[11] ? 11 : Sel[3] ? 3 : Sel[7] ? 7 : Sel[9] ? 9 : Sel[1] ? 1 : 5;   // MEI MSI MTI SEI SSI STI (processor.cc:271-282)
```
`TrapTaken = Commit && (IrqPending || ExceptionValid)`; an interrupt wins over the EX instruction's own exception, as today. Vectored `stvec` adds `4*cause` for interrupts only.

### Implementation notes (phase 2a: mstatus.FS)
- `mstatus.FS` is a real 2-bit WARL field (any value stored, `mstatus` and `sstatus` writes), reset Off. Spike: `FS` is in the sstatus write mask whenever S or F exists (`csrs.cc:591-599`), `compute_mstatus_initial_value` has no FS bits (`csrs.cc:732-741`, so reset = Off), `SD = (FS == 11)` (`adjust_sd`, `csrs.cc:610-620`). `sstatus` exposes FS and SD. XS/VS read 0.
- FS = Off: every FP instruction and every `fflags/frm/fcsr` access (read or write, any operand) is illegal, cause 2, tval 0 (`require_fp` = `float_csr_t::verify_permissions`, `decode_macros.h:182`, `csrs.cc:1688-1690`). The core decodes only OP-FP (no FLW/FSW/FMADD yet, they are illegal anyway).
- Dirty: an FP register write, or a `fflags/frm/fcsr` write (`WRITE_FRD` -> `dirty_fp_state`, `decode_macros.h:128-130`; `float_csr_t::unlogged_write`, `csrs.cc:1709-1711`). `csrrs/csrrc` with rs1 = x0 does not write, so it does not dirty.
- RTL: `csr_file` gains `FpOp` (valid FP instruction in EX) and `FpRegWrite` (it writes an FPR), wired from `FPUValidE`/`FPURegWriteE` in `execute_stage`. Legality is combinational in EX (folded into `CsrIllegal`), `MStatusFS <= Dirty` at the commit edge. An FP instruction with FS = Off still runs the FPU to completion (the hazard unit stalls EX until done) and then traps; the squash discards its result.
- Spike profile: no forced Dirty. The profile does not accrue `fflags`, so an OP-FP that writes no FPR (compares, `fcvt.w`, `fmv.x.w`, `fclass`) restores FS afterwards (Spike would dirty it when a flag is raised).
- Generator: the prologue sets FS = Initial before the first FP instruction; random `mstatus` writes carry a random FS (Off in 10 %), so FP instructions with FS = Off trap in lock-step.

### Implementation notes (phase 2b: generator S window, directed `priv_s_mode.S`, coverage, mutation proof)
- Generator: `RW_CSRS` gains the S CSRs, `0x105` and `0x312` (RV32); `UNKNOWN_CSRS` drops `0x180/0x100`, adds `0x5A8`. `stvec`, `medeleg` and `mideleg` are only ever *read* by random code (a stray value would send a trap to a wild address, or delegate S ECALL and loop the handler); only the S window writes them. The M handler also clears the software `mip` bits on every interrupt (else a pending SSIP/STIP/SEIP re-fires forever) and clears `medeleg` on ECALL from U/S (cause 8/9).
- S handler (`stab`, 10 vector slots all jumping to one body, registers x22/x23 reserved so the M handler cannot clobber them): `sepc += 4` for exceptions, `SPP <- S` for ECALL from U (so the window resumes in S), `sie &= ~0x222` for interrupts (software pending bits cannot be cleared from S), SRET. `stvec` is set in the prologue (direct) and re-written by every window with mode 0-3 (bit 1 is WARL).
- S window (5 % of the body slots): random legal `medeleg` (never bit 9, plus junk in the bits that must read 0) and `mideleg`, readbacks of `medeleg/mideleg/sie/sip/stvec`, random `mie` S bits and software `mip` bits, `mcounteren/scounteren`, MPP = S with random SIE/SPIE/SPP/MPIE, MRET, 3-10 S instructions (counter reads, S CSR accesses, SRET template, WFI, memory, ALU, system words), two ECALLs (cause 9 never delegated; from U after an SRET, `medeleg[8]` resumes in S via the handler, hence the second). TSR is set only when nothing is delegated (the S handler ends in SRET) and cleared at the end.
- FS = Off window (2 %): `mstatus.FS <- 0`, FP instructions / `fflags/frm/fcsr` reads, `FS <- Initial`. Needed so the "FS-Off check removed" mutant is caught by `risc_top` (it is, both XLEN, seed 1234).
- `priv_s_mode.S` (both XLEN, +SPIKE): reset/WARL readback, sstatus/sie/sip views, delegated and non-delegated traps with `sepc/scause/stval/SPP/SPIE/SIE`, M traps ignoring `medeleg`, delegated ECALL from S, SRET (S, U, TSR, MPRV/SPP clear from M), counter gates, WFI (S legal, TW traps), a table-driven interrupt matrix (SSI/STI/SEI x delegated x S/U/M x SIE x MIE, 27 rows in `.data`), M-routed STI beating delegated SEI, vectored `stvec` and `mtvec`. It fits the 3 KiB code limit only because `TO_S/TO_U` are `jal` to one MRET stub and the table lives in `.data`. No interrupt line is driven in compliance runs, so the S line and the `mip` SEIP RMW base are covered by random programs and the CSR env only.
- Coverage: `csr_seq` runs 20 000 items in cycles of 80: 7 directed items (trap to M, `mstatus` MPP = S or U, `mie`, `mideleg`, `mip`, `mcounteren`, MRET), 49 "calm" items that keep the core in S/U (only CSRs legal there, one in five a trap, one in six a WFI), 24 free items. Without it the S/U bins of `irq_cx`, `wfi_cx`, `trap_cx`, `counter_cx` stayed at 97.8-98.8 %. No ignore bins added. `csr_sva`: `deleg_bits` takes `Mideleg` as an argument (a continuous assign was not re-evaluated when only `mideleg` changed; the new stimulus exposed it).
