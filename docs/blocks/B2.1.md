## B2.1 LR/SC and AMOs (A extension)
- Goal:            Execute Zalrsc + Zaamo (`.W`, and `.D` on RV64) on the 5-stage core; the first ISA item Linux needs beyond RV32IM.
- Depends on:      B1.x (precise traps in EX, freeze-on-miss hazard contract, sub-word MEM path)
- Spec:            [docs/linux/ISA_A.md](../linux/ISA_A.md), [docs/linux/modules/AMO_UNIT.md](../linux/modules/AMO_UNIT.md); Unpriv zalrsc.adoc / zaamo.adoc
- Design files:    new: `Design/amo_unit.sv`   modified: `shared_pkg.sv`, `opcode_decoder.sv`, `risc_control_unit.sv`, `decode_stage.sv`, `execute_stage.sv`, `memory_stage.sv`, `riscv_processor.sv`, `csr_defs.sv`, `csr_file.sv`
- shared_pkg/csr_defs additions: `opcode_t::AMO = 7'b010_1111`; `amo_op_t` (values = funct5); `` `MISA_A`` (misa bit 0 set)
- Ports added:     `opcode_decoder.funct5/Rs2/Amo`; `risc_control_unit.AmoD`; `decode_stage.AmoE/AmoOpE`; `execute_stage.AmoE/AmoOpE → AmoM/AmoOpM`; `memory_stage.AmoM/AmoOpM` (1 bit + `amo_op_t`, carried D→E→M)
- Hazard requests: none new. The AMO* read half holds `CacheHitM` low for one extra cycle, so the existing "any miss freezes F..W" rule covers the read-then-write (AMO_UNIT.md §3: folding `AmoBusyM` into `CacheHitM`).
- Verification:    ISS (`riscv_iss_pkg::amo_execute`), Spike lock-step (`rv<XLEN>imaf`), commit checker checks SC/AMO* stores at cache-write completion, generator emits AMO*/LR-SC pairs/lone SC/misaligned/illegal encodings, decode env (predictor AMO case, `AmoOpE_cg`), memory env (reservation + RMW model, `AmoOp_cg`, random `ExtraStall`), `memory_sva` atomic properties, execute predictor (AMO* misaligned = cause 6)
- Exit criteria:   all 9 tops pass at XLEN 32/64; Spike 0 mismatches; mutation proof below. `rv32ua-p-*` not run yet: needs the B0.4 compliance harness (unified RAM at 0x8000_0000)
- Rollback:        `git revert` of the B2.1 commit (no parameter switch: atomics are part of the ISA once `misa.A = 1`)

### Microarchitecture
- Decode: AMO sets `Amo`, `MemToReg`, `RegWrite`, `ALUSrc` with a zero immediate (address = rs1); `MemRead` unless SC, `MemWrite` unless LR. Illegal: funct3 not `.W`/`.D` (`.D` only on RV64), reserved funct5, LR with rs2 ≠ x0. `aq`/`rl` ignored (in-order, blocking cache).
- EX: AMO* both reads and writes, so its misaligned check takes the store branch (cause 6); LR → 4, SC → 6.
- MEM (`memory_stage`):
  - LR: cache read; on hit `{ResValid, ResAddr} ← {1, addr}`.
  - SC: writes rs2 only if `ResValid && ResAddr == addr`; rd = 0 / 1; reservation cleared when it completes.
  - AMO*: read (old value → `AtomicResult`), then write `amo_unit(old, rs2)`; rd = old.
  - `AtomicDone`: SC / AMO* finished while MEM/WB is still frozen (I-cache miss): no further cache access, result held. Without it a frozen AMO would apply twice and a frozen SC would fail its retry.
- `amo_unit`: combinational; `.W` sign-extends rs2 so signed and unsigned compares order 32-bit values correctly on RV64.

### Decisions that differ from docs/linux and PLAN_B
| Item | Docs said | Implemented | Why |
|---|---|---|---|
| Reservation clear | on any trap and xRET | only by SC (and reset) | Spike (golden model) does not clear on trap/MRET (`mret.h`, `take_trap`), so the lock-step stays exact; spec-legal; Linux drops stale reservations itself with an SC on trap return |
| Reservation granule | 8-byte doubleword | exact LR address | matches Spike's default (`load_reservation_set_mask = ~0`); fewer bits |
| Misaligned LR/SC/AMO | access fault 5 / 7 | address-misaligned 4 / 6 | both allowed by Zalrsc/Zaamo; Spike raises misaligned; reuses the existing EX check |
| Cache port `CPUAmo` / `AmoBusyM` | new port + hazard request | none: MEM sequences read then write on the existing port | no cache change; `cache.sv` untouched |
| Uncached AMO → access fault | yes | n/a | no uncached region exists yet (B7); revisit with the interconnect |

Every mutant is caught by at least one environment. The random core program rarely
repeats an SC after one LR or freezes on an I-cache miss exactly at an AMO, which is
why `mem_top` (dense atomics + `ExtraStall`) and `memory_sva` carry those cases.
