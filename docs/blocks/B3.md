### Commit-point timing (all of B3)
The commit point stays EX (PLAN_B §2.3). For the instruction in EX in cycle *t* with
`Commit = ValidE && !StallE` (`execute_stage.sv:457`):
- every legality decision (privilege, counter gate, MRET/WFI in U) is combinational in *t* and raises `TrapTaken` in *t*, like today's `CsrIllegal` (`csr_file.sv:225`);
- every state change (`PrivMode`, `MStatusMPP/MPRV/TW`, `Mcounteren`, and the setting of `WfiWait`) happens at the rising edge that ends *t*; the instruction in EX at *t*+1 sees the new value. No flush is needed: the next instruction reads all of this state in EX, never in D;
- older instructions in M/W are unaffected; no state changes while `StallE` (the existing `!Commit |=> $stable` rule, `csr_sva.sv:33`, extends to the new registers). Exception: `WfiWait` clears on `WfiWake` without a commit (B3.4), so it has its own wake assertion instead.

### B3.2 Privilege mode and checks

State in `csr_file`. The internal names are bound by `csr_sva (.*)`, so they are part of the contract:

| Register | Type | Reset |
|---|---|---|
| `PrivMode` (also the output port) | `priv_mode_t` | `MachineMode` (Spike `processor.cc:111`) |
| `MStatusMPP` | `priv_mode_t` (only `UserMode`/`MachineMode` are ever stored) | `UserMode` (Spike `csrs.cc:737`) |
| `MStatusMPRV`, `MStatusTW` | 1 bit each | 0 |
| `Mcounteren` | `logic [2:0]` | 0 |

Behaviour (pseudo-RTL; `Commit`, `TrapTaken`, `MretTaken` as today):
```systemverilog
// Legality that depends on PrivMode (cause 2, mtval 0). Folded into CsrIllegal,
// so the existing cause/mtval paths (csr_file.sv:226-227, 290) need no change.
CounterGated = (PrivMode == UserMode) && CsrAccess &&
               ((CsrIndex inside {cycle,    cycleh}    && !Mcounteren[`CY]) ||
                (CsrIndex inside {time_csr, timeh_csr} && !Mcounteren[`TM]) ||
                (CsrIndex inside {instret,  instreth}  && !Mcounteren[`IR]));
PrivIllegal  = (CsrAccess && (CsrIndex[9:8] > PrivMode)) || CounterGated ||
               (mret && (PrivMode != MachineMode)) ||
               (Wfi && (PrivMode == UserMode) && MStatusTW);
CsrIllegal   = (CsrAccess && !CsrExists) || PrivIllegal;

// M interrupts are always enabled below M (Priv "Machine Interrupt Registers")
InterruptPending = (MStatusMIE || (PrivMode != MachineMode)) && (<today's MEI/MSI/MTI terms>);

// Trap entry (adds to Trap_Entry, csr_file.sv:286):
MStatusMPP <= PrivMode;  PrivMode <= MachineMode;               // MPRV, TW untouched
// MRET (adds to Return_From_Trap, csr_file.sv:295):
PrivMode <= MStatusMPP;  MStatusMPP <= UserMode;
if (MStatusMPP != MachineMode) MStatusMPRV <= 1'b0;
// mstatus write (csr_file.sv:305):
MStatusMPP  <= (CsrWriteData[`MPPE:`MPPS] == 2'b11) ? MachineMode : UserMode;
MStatusMPRV <= CsrWriteData[`MPRV];  MStatusTW <= CsrWriteData[`TW];
// mcounteren write:
Mcounteren  <= CsrWriteData[2:0];
```
- ECALL: `execute_stage.sv:484` becomes `TrapsE = (PrivModeE == UserMode) ? EcallUOrUserExternalInterrupt : EcallMOrMachineExternalInterrupt;` with `PrivModeE` = `csr_file.PrivMode`. Cause 8 from U, 11 from M (Spike `insns/ecall.h:1-9`). EBREAK stays 3 in both modes.
- MRET in U → illegal (Spike `insns/mret.h:1`). MRET semantics match `insns/mret.h:4-10,24`: MPRV is cleared iff MPP ≠ M, and MPP ← U because U exists.
- CSR check order does not matter: existence, read-only write (decode, unchanged, `decode_stage.sv:400-406`), privilege (`csrs.cc:44-46`) and the counter gate (`csrs.cc:1455-1466`) all give cause 2 with mtval 0. The privilege-dependent checks live in `csr_file` (EX), because decode cannot see the `PrivMode` that an MRET in EX is about to change.
- MPRV has no architectural effect in B3: there is no PMP and no translation, and Spike `mmu_t::pmp_ok` returns true with 0 PMP regions (`mmu.cc:536-537`). It is plumbed to the D side in B5.3.
- SRET and SFENCE.VMA stay illegal (no S).
- `exc_cause_t` is not added: `traps_t` already encodes causes 0–11 (`shared_pkg.sv:193-208`).

### B3.3 Counters (Zicntr) and time

- `cycle/instret(h)` are unchanged (B1.6). B3 adds only the U-mode gate above (`mcounteren.x = 0` → illegal in U; M is never gated). With no S-mode, `mcounteren` gates U directly (`csrs.cc:1458`; `sctr_ok` needs S, `:1460`).
- **mtime before the CLINT.** `riscv_processor` gets input `MTime[63:0]`, passed unchanged to `execute_stage.MTime` → `csr_file.MTime`. Until B7.3, `risc_top` drives it from a free-running counter: reset (`!rst`) to `64'h0000_0000_FFFF_FF00`, `+1` every `posedge clk`. The offset keeps `time ≠ mcycle`, so a mux mutant is visible, and makes `timeh` roll over after 256 cycles. B7.3 connects the CLINT `mtime` to the same port. `execute_top` and `csr_top` drive the port from their sequences (random 64-bit, changing every cycle).
- **Keeping ISS and Spike equal.** Today `mcycle` reaches both models as a by-value input of each step (`commit_checker.sv:344-345`, `csr_rdata`), and Spike patches `rd` after the step (`spike_dpi.cc:204-211`). `time` uses the same per-step input channel, but carries the TB's `MTime` sampled at the commit (negedge, the same cycle as the DUT's combinational read), not the DUT's read value, so a DUT read-path bug is caught:
  - `commit_checker`: new input `logic [63:0] MTime` (auto-connected by the existing `bind DUT commit_checker (.*)`, `risc_top.sv:223`); it passes it to `iss.step(..., MTime)` and `spike_step(..., 64'(csr_rdata), MTime, ...)`.
  - ISS: `step(bit ext, bit tmr, bit sw, xlen_t csr_rdata, logic [63:0] mtime)`; `0xC01` reads `mtime[XLEN-1:0]`, `0xC81` (RV32) reads `mtime[63:32]`, both behind the same gate as `cycle`.
  - Spike: `s->time->sync(mtime)` before `proc->step(1)` (`time_counter_csr_t::sync`, `csrs.cc:1415-1418`; `state_t::time`, `processor.h:191`). There is no rd patch for `time`, so Spike's own CSR path (including the `mcounteren` gate and `timeh`) is exercised. `sync()` only touches STIP with Sstc, which is off (`csrs.cc:1404`).
  - Monotonicity holds by construction of the TB counter; the CLINT (B7.3) gets its own check.

### B3.4 WFI

- **Decode**: WFI (`0x10500073`, already legal, `decode_stage.sv:437`) now also sets `WfiD` → registered `WfiE` (reset/flush 0).
- **Legality**: illegal only in U with `TW = 1` (`PrivIllegal` above). In U with `TW = 0` it is legal because S is not implemented (Spike `insns/wfi.h:1-10`: `require_privilege(PRV_S)` only `if extension_enabled('S')`). In M it is always legal.
- **Stall**: WFI itself retires in EX like a NOP. Like any instruction, it takes a pending enabled interrupt first (mepc = WFI). After it retires, the *next* instruction is held in EX until an interrupt is pending locally:
```systemverilog
WfiWake  = |(MipValue & MieValue);          // ignores mstatus.MIE and PrivMode
WfiStall = WfiWait && !WfiWake;              // output, → execute_stage.WfiStallE
always_ff: if (Commit && Wfi && !TrapTaken) WfiWait <= 1'b1;
           else if (WfiWake)               WfiWait <= 1'b0;   // reset 0
```
  `hazard_unit`: `StallF/StallD/StallE |= WfiStallE`, `FlushM = TrapIsSet || ((FPUStall || WfiStallE) && !MemStall)`. This is a separate input, not folded into `FPUValidE` like `DivWaitE` (`riscv_processor.sv:599`): `FPUStall = FPUValidE && !FPUDoneE` would release the hold when an FP instruction behind the WFI finishes. On wake, the held instruction commits in the same cycle the line is seen, so an enabled interrupt is taken on it with `mepc = WFI + 4`, as the Priv spec requires.
- **Operand refresh while held** (added during implementation): while the next instruction is held, its producer retires from WB and EX forwarding from it ends, so the ID/EX `RD1E`/`RD2E` would be stale (`li x10,123; wfi; add x11,x10,x10` gave 0, not 246). On the `StallE && !FlushE` branch, `decode_stage` loads `RD1E`/`RD2E` from `ResultW` when `RegWriteW && RdW != 0 && RdW == Rs1E/Rs2E`. This holds for every `StallE` cause and is invisible to the architecture.
- **Lock-step**: compatible, as long as the ISS and Spike keep WFI as a NOP (`wfi_as_nop = true`, `spike_dpi.cc:139`; ISS `riscv_iss_pkg.sv:508`). The checker is commit-driven. The DUT's wait lies between two commits, and the next commit is stepped with the lines sampled in that cycle, so the models see exactly what the DUT saw. Spike's real WFI (`wfi_as_nop = false`) is *not* used: it re-checks `mip & mie` at the next step (`execute.cc:278`, `processor.cc:317-318`). If the DUT wakes and a cache miss then delays the next commit past the end of a 1–3-cycle TB pulse (`risc_test_pkg.sv:180-194`), Spike would execute nothing and the models would diverge.
- **No timeout**: with `mie = 0` the hart sleeps forever (spec-legal). The generator therefore enables a wake source before every WFI (below). `risc_compliance_test` (no interrupts) must not execute WFI with `TW = 0`.
- Benefit note: in RTL simulation the clock keeps running while the hart sleeps, so the saving is instruction activity, not simulated cycles. It is implemented because it is in the plan of record.
